# Submission package

Camera-ready material for the Chess Algorithm manuscript, in Elsevier
`elsarticle` format, addressed to **Knowledge-Based Systems** (Elsevier). The
package lives in `knowledge-based-systems/`.

## How it is built

The manuscript is one source, `paper.qmd` at the repository root, which renders
to three formats. The Elsevier build is the third, and one command does all of
it:

```sh
python src/build_submission.py
```

That renders `paper.qmd --to elsevier-pdf`, collects the LaTeX source, the
bibliography, the class and bibliography-style files and only the figures the
source actually includes, then **re-compiles the collected copy in a scratch
directory** and fails if the log shows an undefined citation or reference or a
dropped glyph. The package is therefore checked to build on its own, which is
what Elsevier's system does with it.

The script drives the render itself rather than trusting you to have run it,
because rendering any *other* format of `paper.qmd` deletes `paper.tex` — only
the Elsevier format sets `keep-tex`. Pass `--no-render` to reuse an existing
`paper.tex`, `--no-verify` to skip the re-compile.

Everything the script generates is gitignored, in the same way `_article/` is:
the committed things are the manuscript source and the documents below, and the
package is rebuilt from them.

Format details live in the `elsevier-pdf` block of `paper.qmd`: `elsarticle`
with `preprint,3p,onecolumn,number`, `elsarticle-num` bibliography style,
journal name set for the running footer. Single column is deliberate — the
transposed comparison tables carry one column per test function and do not
survive a two-column layout.

## What is in `knowledge-based-systems/`

Checked against the journal's Guide for Authors (a local PDF copy sits in this folder; it is not committed).

| File | Upload as |
|---|---|
| `chess_algorithm_manuscript.pdf` | Manuscript (PDF, used for review) |
| `chess_algorithm_manuscript_latex_source.zip` | LaTeX source (editable source files are required) |
| `figures_for_upload/Figure_1 ...` | Each figure as a separate file, numbered in order of appearance |
| `highlights.docx` | Highlights (separate editable file with "highlights" in the name; 5 bullets, each within 85 characters) |
| `cover_letter.md` / `.pdf` | Cover letter (not required by the guide) |
| `declaration_of_interest.md` | Content reference only, see below |

**Declaration of competing interests:** the guide asks for the Word document
generated by Elsevier's declarations tool, uploaded at the "attach files" step.
Complete the tool ("I have nothing to declare" applies) and upload the .docx it
produces; the `.md` here holds the same wording for reference. The CRediT
statement, competing-interest declaration, funding statement, generative-AI
declaration and data-availability statement are also inside the manuscript,
before the appendix.

There is no graphical abstract: the guide does not ask for one.

## Open items: these need you, not the build

1. **Postal addresses.** The guide requires the full name *and postal address*
   (with country) of each affiliation on the title page. `paper.qmd` currently
   gives department, university, city and country only.
2. **Generative-AI declaration.** The guide's template names the tool
   ("the author(s) used [NAME OF TOOL / SERVICE] in order to [REASON]"). The
   manuscript currently says "a large language model assistant". Decide whether to
   name the tool and confirm the listed uses are complete.
3. **Research data (Option C).** The guide requires depositing research data in a
   relevant repository and citing and linking it in the article. A GitHub link
   alone does not meet that. Archive the repository on Zenodo (its GitHub
   integration issues a DOI per release), then cite the DOI in the paper as a
   `[dataset]`/software reference.
4. **Length.** The guide prefers no more than 20 double-spaced pages including
   tables and figures. The manuscript is far longer.
5. **Cover letter salutation** ("Dear Editor") and **Dr. Mirjalili's editorial
   roles** (declare at submission if he holds any at this journal).
6. ORCID and institutional details are entered in Editorial Manager.

## Fallback: Cluster Computing

**Cluster Computing is published by Springer, not Elsevier.** `elsarticle` does
not apply. It needs the Springer Nature LaTeX template (`sn-jnl.cls`), which is
a different front-matter structure, a different bibliography style and a
different figure convention. The manuscript body and figures carry over but the
front matter has to be rebuilt.
